# 다중 필터 체인

## 1. 필터체인 동작 원리

Spring Security는 FilterChainProxy라는 핵심 컴포넌트를 통해 HTTP 요청을 처리합니다. FilterChainProxy는 여러 개의 SecurityFilterChain을 관리하며, 각 SecurityFilterChain은 URL 패턴이나 요청 조건에 따라 특정 필터 목록을 포함합니다. 요청이 들어오면 FilterChainProxy가 해당 요청과 매핑되는 SecurityFilterChain을 찾아서 해당 필터들을 순차적으로 실행합니다.

## 2. 다중 필터체인 구성

다중 필터체인을 설정하려면 SecurityFilterChain 빈을 여러 개 정의하거나, Spring Boot에서는 SecurityFilterChain을 반환하는 @Bean 메서드를 여러 개 만들어야 합니다. Spring Security 5.7 이상부터는 @Configuration 클래스에서 @Bean으로 정의하는 방식이 권장됩니다.

 - __요청 매핑__: 요청이 들어오면 FilterChainProxy가 securityMatcher()에 정의된 패턴을 확인합니다. 예를 들어, /api/users는 첫 번째 필터체인에 매핑되고, /web/home은 두 번째 필터체인에 매핑됩니다.
 - __우선순위__: 여러 필터체인이 매핑될 수 있는 경우, Spring Security는 정의된 순서(빈 등록 순서)를 기준으로 첫 번째로 매칭되는 필터체인을 선택합니다. 명시적으로 순서를 조정하려면 @Order 어노테이션을 사용할 수 있습니다.
 - __필터 실행__: 매핑된 SecurityFilterChain 내의 필터들이 순차적으로 실행됩니다. 예를 들어, /api/** 요청은 BasicAuthenticationFilter를 거치고, /web/** 요청은 FormLoginFilter를 거칩니다.
 - __매핑되지 않은 요청__: 어떤 필터체인에도 매핑되지 않은 요청(예: /other)은 Spring Security를 거치지 않고 애플리케이션으로 전달됩니다(기본적으로 무시됨).

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain apiSecurityFilterChain(HttpSecurity http) throws Exception {
        http
            .securityMatcher("/api/**") // "/api/**" 경로에만 적용
            .authorizeHttpRequests(authorize -> authorize
                .anyRequest().authenticated()
            )
            .httpBasic(Customizer.withDefaults());
        return http.build();
    }

    @Bean
    public SecurityFilterChain webSecurityFilterChain(HttpSecurity http) throws Exception {
        http
            .securityMatcher("/web/**") // "/web/**" 경로에만 적용
            .authorizeHttpRequests(authorize -> authorize
                .anyRequest().permitAll()
            )
            .formLogin(Customizer.withDefaults());
        return http.build();
    }
}
```

### 2-1. 다중 필터체인 주의사항

FilterChainProxy는 등록된 SecurityFilterChain 목록을 순차적으로 확인하며, 요청과 매핑되는 첫 번째 필터체인을 선택합니다. 즉, __가장 먼저 매칭된 필터체인만 실행되고 나머지는 무시됩니다.__ Spring Security는 "하나의 요청에 대해 하나의 필터체인만 적용"하는 원칙을 따르기 때문에, 동일한 경로를 처리하는 여러 필터체인이 있더라도 충돌 없이 단일 필터체인이 선택됩니다.

 - `우선순위 결정`
```java
// 1. 빈 정의 순서
// Spring Boot에서 @Bean으로 정의된 SecurityFilterChain은 기본적으로 @Configuration 클래스 내에서 정의된 순서(코드 상단에서 하단으로)대로 등록됩니다.
@Bean
public SecurityFilterChain chain1(HttpSecurity http) throws Exception {
    http.securityMatcher("/api/**").authorizeHttpRequests(auth -> auth.anyRequest().authenticated());
    return http.build();
}

@Bean
public SecurityFilterChain chain2(HttpSecurity http) throws Exception {
    http.securityMatcher("/api/**").authorizeHttpRequests(auth -> auth.anyRequest().permitAll());
    return http.build();
}

// 명시적 우선순위 설정 (@Order)
// @Order 어노테이션을 사용하면 필터체인의 우선순위를 명시적으로 지정할 수 있습니다. 값이 낮을수록 높은 우선순위를 가집니다.
// @Order(1)인 chain1이 @Order(2)인 chain2보다 우선순위가 높아 /api/** 요청에 대해 chain1만 실행됩니다.
@Bean
@Order(1)
public SecurityFilterChain chain1(HttpSecurity http) throws Exception {
    http.securityMatcher("/api/**").authorizeHttpRequests(auth -> auth.anyRequest().authenticated());
    return http.build();
}

@Bean
@Order(2)
public SecurityFilterChain chain2(HttpSecurity http) throws Exception {
    http.securityMatcher("/api/**").authorizeHttpRequests(auth -> auth.anyRequest().permitAll());
    return http.build();
}
```

### 2-2. 다중 필터체인 설계

Spring Security에서 다중 필터체인을 설계하는 것은 애플리케이션의 다양한 요구사항(예: API 보안, 웹 페이지 보안, 관리자 경로 등)을 효과적으로 분리하고 관리하는 데 유용합니다.

 - __중복 정의의 위험__: 동일한 경로에 대해 여러 필터체인을 정의하면 의도치 않게 후순위 필터체인이 실행되지 않을 수 있으므로, 디버깅이 어려워질 수 있습니다. 따라서 경로 매핑(securityMatcher)을 명확히 구분하거나, 우선순위를 의도적으로 설정하는 것이 좋습니다.
 - __로그 확인__: 애플리케이션 실행 시 Spring Security가 어떤 필터체인이 어떤 경로에 매핑되었는지 로그로 출력하므로, 이를 통해 실제 적용 순서를 확인할 수 있습니다.
 - __단일 책임 원칙__: 가능하면 동일한 경로를 여러 필터체인이 처리하도록 설계하지 않고, 경로별로 책임을 분리하는 것이 유지보수에 유리합니다.
 - __(1) 경로 매핑 명확화__
    - securityMatcher()를 사용해 각 필터체인이 처리할 경로를 명확히 구분합니다.
    - 중복 매핑(예: /api/*와 /api/users/*)을 피하고, 필요한 경우 더 구체적인 경로가 높은 우선순위를 갖도록 설정합니다.
 - __(2) 우선순위 설정__
    - @Order 어노테이션으로 필터체인 실행 순서를 제어합니다. 값이 낮을수록 먼저 실행됩니다.
    - 일반적으로 더 구체적인 경로(예: /admin/*)를 상위 우선순위로, 포괄적인 경로(예: /*)를 낮은 우선순위로 설정합니다.
 - __(3) 인증/인가 방식 분리__
    - API는 JWT나 OAuth2를, 웹은 세션 기반 폼 로그인을 사용하는 식으로 각 필터체인에 적합한 인증 방식을 적용합니다.
    - 예: .httpBasic(), .formLogin(), .oauth2ResourceServer() 등.
 - __(4) 공통 설정 재사용__
    - 모든 필터체인에 적용할 공통 설정(예: UserDetailsService, PasswordEncoder)은 별도로 정의해 재사용합니다.
```java
@Bean
public UserDetailsService userDetailsService() {
    return new CustomUserDetailsService();
}

@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```
 - __(5) CSRF 관리__
    - API 경로는 CSRF를 비활성화(csrf.disable())하고, 웹 경로는 활성화(csrf.withDefaults())하는 식으로 요구사항에 맞게 조정합니다.

### 2-3. 다중 필터체인 예시

 - /api/**: REST API 엔드포인트로, 토큰 기반 인증(JWT) 필요.
 - /web/**: 일반 웹 페이지로, 폼 로그인 필요.
 - /admin/**: 관리자 페이지로, 추가 권한 체크 필요.
 - /public/**: 인증 없이 접근 가능.
```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    // /api/**: REST API 엔드포인트로, 토큰 기반 인증(JWT) 필요
    @Bean
    @Order(1)
    public SecurityFilterChain apiFilterChain(HttpSecurity http) throws Exception {
        http
            .securityMatcher("/api/**") // API 경로에만 적용
            .authorizeHttpRequests(auth -> auth
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults())) // JWT 인증
            .csrf(csrf -> csrf.disable()); // API는 CSRF 비활성화
        return http.build();
    }

    // /web/**: 일반 웹 페이지로, 폼 로그인 필요
    @Bean
    @Order(2)
    public SecurityFilterChain webFilterChain(HttpSecurity http) throws Exception {
        http
            .securityMatcher("/web/**") // 웹 경로에만 적용
            .authorizeHttpRequests(auth -> auth
                .anyRequest().authenticated()
            )
            .formLogin(Customizer.withDefaults()) // 폼 로그인
            .csrf(Customizer.withDefaults()); // CSRF 활성화
        return http.build();
    }

    // /public/**: 인증 없이 접근 가능
    @Bean
    @Order(3)
    public SecurityFilterChain publicFilterChain(HttpSecurity http) throws Exception {
        http
            .securityMatcher("/public/**") // 공개 경로
            .authorizeHttpRequests(auth -> auth
                .anyRequest().permitAll()
            )
            .csrf(csrf -> csrf.disable());
        return http.build();
    }

    // 기본 필터체인
    // 매핑되지 않은 경로를 처리하기 위해 필터체인을 낮은 우선순위로 추가
    @Bean
    @Order(100)
    public SecurityFilterChain defaultFilterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .anyRequest().denyAll() // 나머지 요청 차단
            );
        return http.build();
    }
}
```
