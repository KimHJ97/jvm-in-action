# 필터 체인(Filter Chain)

Spring Security의 필터체인(Filter Chain) 은 Spring Security의 핵심 구조 중 하나로, HTTP 요청이 들어올 때 이를 가로채서 인증(Authentication), 인가(Authorization), 세션 관리, CSRF 보호 등 다양한 보안 처리를 수행하는 필터들의 집합입니다.

Spring Security는 Filter 기반으로 작동하며, 요청이 컨트롤러로 가기 전에 여러 보안 필터들이 순차적으로 동작합니다. 이 필터들의 조합을 SecurityFilterChain 이라고 하고, 이를 통해 인증, 인가, CSRF, 세션 등의 처리를 담당합니다. 필요 시 커스텀 필터를 추가하거나 기존 필터의 순서를 조절할 수 있습니다.

 - Spring Security는 Servlet Filter 기반으로 동작합니다.
 - 여러 개의 보안 관련 필터(Filter) 들이 하나의 FilterChainProxy 안에 체인 형태로 구성되어 있음.
 - DispatcherServlet 앞에서 작동해서 요청을 먼저 가로채고 보안 처리를 합니다.

## 1. 주요 Spring Security Filter

 - ChannelProcessingFilter: HTTPS 강제 여부 검사
 - WebAsyncManagerIntegrationFilter: 비동기 요청을 보안 컨텍스트에 통합
 - SecurityContextPersistenceFilter: SecurityContext (세션)을 로딩/저장
 - HeaderWriterFilter: 보안 관련 HTTP 헤더 설정 (예: X-Frame-Options)
 - CsrfFilter: CSRF 보호
 - LogoutFilter: 로그아웃 처리
 - UsernamePasswordAuthenticationFilter: 폼 로그인 처리 (아이디/비밀번호)
 - BasicAuthenticationFilter: HTTP Basic 인증 처리
 - BearerTokenAuthenticationFilter: JWT 토큰 기반 인증 처리 (OAuth2 등)
 - SecurityContextHolderFilter: 인증 정보 보관
 - ExceptionTranslationFilter: 인증/인가 예외 처리 및 적절한 응답 처리
 - FilterSecurityInterceptor: 인가 (권한 확인)

## 2. 주요 설정

Spring Security의 주요 설정은 요청 매핑, 인증/인가, CSRF, 세션 관리, 예외 처리 등으로 나눌 수 있으며, 다중 필터체인에서는 이를 경로별로 적절히 조합해 사용합니다. 각 설정은 애플리케이션의 보안 요구사항에 따라 조정되며, 공통 요소는 별도 빈으로 분리해 재사용성을 높이는 것이 좋습니다.

 - `요청 매핑 설정`
    - 필터체인이 적용될 경로를 정의
    - securityMatcher()는 필터체인 자체의 매핑을 정의
    - requestMatchers()는 authorizeHttpRequests() 내에서 세부적인 경로별 권한을 설정할 때 사용
```java
http.securityMatcher("/api/**")
    .authorizeHttpRequests(auth -> auth
        .requestMatchers("/api/admin/**").hasRole("ADMIN")
        .anyRequest().authenticated()
    );

```

 - `커스텀 필터 추가`
    - addFilterBefore, addFilterAfter, addFilter 등을 사용해서 커스텀 필터를 넣을 수 있다.
```java
http
    .addFilterBefore(
        new MyCustomFilter(), 
        UsernamePasswordAuthenticationFilter.class
    );
```

 - `인증 설정`
    - formLogin()
        - 폼 기반 로그인 설정(웹 애플리케이션에 주로 사용)
        - 주요 옵션: 로그인 페이지, 성공/실패 핸들러 등
        - 예: .formLogin(form -> form.loginPage("/login").permitAll())
    - httpBasic()
        - 기본 HTTP 인증(주로 API에 사용)
        - 예: .httpBasic(Customizer.withDefaults())
    - oauth2Login()
        - OAuth2 기반 로그인(소셜 로그인 등)
        - 예: .oauth2Login(oauth -> oauth.loginPage("/oauth2/login"))
    - oauth2ResourceServer()
        - JWT나 불투명 토큰으로 API 인증
        - 예: .oauth2ResourceServer(oauth -> oauth.jwt(Customizer.withDefaults()))

 - `인가 설정`
    - 요청에 대한 접근 권한을 정의
    - .anyRequest(): 모든 요청에 대한 기본 규칙.
    - .requestMatchers(): 특정 경로에 대한 규칙.
    - .permitAll(): 인증 없이 허용.
    - .authenticated(): 인증 필요.
    - .hasRole() / .hasAuthority(): 특정 역할/권한 필요.
```java
http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/public/**").permitAll()
    .requestMatchers("/admin/**").hasRole("ADMIN")
    .anyRequest().authenticated()
);
```

 - `CSRF 설정`
    - CSRF(Cross-Site Request Forgery) 보호를 활성화/비활성화.
    - API는 보통 비활성화, 웹은 활성화
    - 비활성화: .csrf(csrf -> csrf.disable())
    - 활성화: .csrf(Customizer.withDefaults())

 - `세션 관리`
    - 세션 생성 및 관리 정책 설정
    - .sessionCreationPolicy(SessionCreationPolicy.STATELESS): 세션 사용 안 함(주로 API).
    - .sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED): 필요 시 세션 생성(기본값).
```java
http.sessionManagement(session -> session
    .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
);
```

 - `예외 처리`
    - 인증 실패(401)나 권한 부족(403) 시 동작 정의
    - .authenticationEntryPoint(): 인증 실패 시 응답(예: 로그인 페이지 이동, JSON 반환).
    - .accessDeniedHandler(): 권한 부족 시 응답.
```java
http.exceptionHandling(ex -> ex
    .authenticationEntryPoint(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED))
    .accessDeniedHandler(new CustomAccessDeniedHandler())
);
```

 - `CORS 설정`
    - Cross-Origin Resource Sharing 설정
    - API에서 다른 도메인 요청을 허용할 때 사용
```java
http.cors(cors -> cors.configurationSource(corsConfigurationSource()));

// CorsConfigurationSource 빈 정의
@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOrigins(List.of("http://localhost:3000"));
    config.setAllowedMethods(List.of("GET", "POST"));
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return source;
}
```
