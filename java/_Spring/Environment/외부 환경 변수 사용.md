# 외부 환경 변수 사용

## 1. 외부 환경 변수 가져오기

### 1-1. @Value 어노테이션

 - `기본 사용법`
```java
@Component
public class ValueExampleService {
    
    @Value("${server.port}")
    private int serverPort;
    
    @Value("${app.name}")
    private String appName;
    
    // 기본값 설정
    @Value("${app.timeout:30}")
    private int timeout;
    
    // 문자열 기본값
    @Value("${app.description:Default Description}")
    private String description;
}
```
<br/>

 - `SpEL(Spring Expression Language) 사용`
```java
@Component
public class SpELExampleService {
    
    // 환경변수를 대문자로 변환
    @Value("#{environment['app.name'].toUpperCase()}")
    private String upperAppName;
    
    // 조건부 값 설정
    @Value("#{environment['app.debug'] == 'true' ? 'DEBUG' : 'INFO'}")
    private String logLevel;
    
    // 시스템 프로퍼티와 결합
    @Value("#{systemProperties['user.home'] + '/' + environment['app.config.dir']}")
    private String configPath;
    
    // 리스트 타입
    @Value("#{environment['app.servers'].split(',')}")
    private List<String> servers;
}
```
<br/>

### 1-2. Environment 인터페이스

```java
@Service
public class EnvironmentService {
    
    @Autowired
    private Environment env;
    
    public void useEnvironment() {
        // 기본 사용법
        String serverPort = env.getProperty("server.port");
        
        // 타입 지정
        Integer port = env.getProperty("server.port", Integer.class);
        
        // 기본값 지정
        String appName = env.getProperty("app.name", "DefaultApp");
        
        // 필수 프로퍼티 (없으면 예외 발생)
        String requiredProp = env.getRequiredProperty("database.url");
        
        // 프로파일 확인
        String[] activeProfiles = env.getActiveProfiles();
        String[] defaultProfiles = env.getDefaultProfiles();
        
        // 프로파일 조건 확인
        boolean isDevProfile = env.acceptsProfiles(Profiles.of("dev"));
        
        // 프로퍼티 존재 확인
        boolean hasProperty = env.containsProperty("custom.property");
    }
}
```

### 1-3. @ConfigurationProperties

환경 변수를 POJO 클래스로 매핑하는 방식입니다. 여러 설정값을 그룹핑해서 관리할 때 유리합니다.

 - `예시 데이터`
```bash
# AppProperties 예시
app.name=MyApplication
app.version=1.0.0
app.timeout=30
app.servers[0]=server1.example.com
app.servers[1]=server2.example.com
app.config.env=production
app.config.debug=false

# DatabaseProperties 예시
database.primary.url=jdbc:mysql://primary-db:3306/mydb
database.primary.username=user1
database.primary.password=pass1
database.primary.driver=com.mysql.cj.jdbc.Driver

database.secondary.url=jdbc:mysql://secondary-db:3306/mydb
database.secondary.username=user2
database.secondary.password=pass2
database.secondary.driver=com.mysql.cj.jdbc.Driver

database.pool.min-size=5
database.pool.max-size=20
database.pool.timeout=30000
```

 - `ConfigurationProperties 대상 활성화`
```java
// 특정 클래스를 지정
@SpringBootApplication
@EnableConfigurationProperties({
    AppProperties.class,
    DatabaseProperties.class
})
public class MyApplication {
    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }
}

// 패키지 스캔
@SpringBootApplication
// @ConfigurationPropertiesScan("com.example.config") // 특정 패키지 스캔
@ConfigurationPropertiesScan // 현재 패키지부터 스캔
public class MyApplication {
    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }
}
```

    }

### 1-4. System.getenv() / System.getProperty() 직접 사용

스프링의 추상화 없이 순수 자바 방식으로 환경 변수를 읽을 수도 있습니다.

```java
String osEnv = System.getenv("APP_NAME");       // OS 환경변수
String sysProp = System.getProperty("app.name"); // JVM 시스템 프로퍼티
```

## 2. 외부 환경 변수 고급

### 2-1. @ConfigurationPropertiesBinding과 Converter

```java

// 커스텀 컨버터
@Component
@ConfigurationPropertiesBinding
public class DurationConverter implements Converter<String, Duration> {
    @Override
    public Duration convert(String source) {
        return Duration.parse(source);
    }
}

@Getter
@Setter
@Component
@ConfigurationProperties(prefix = "app")
public class AppConfigWithConverter {
    private Duration timeout; // PT30S 형태의 문자열을 Duration으로 변환
    private LocalDateTime startTime; // ISO 형태의 문자열을 LocalDateTime으로 변환
}
```
<br/>

### 2-2. ConstructorBinding

 - Spring Boot 2.6+ 부터는 @ConstructorBinding이 없어도 생성자 바인딩이 가능
```java
@ConfigurationProperties(prefix = "app")
@Getter
public class AppProperties {
    private final String name;
    private final String version;
    private final int timeout;
    private final Security security;
    
    @ConstructorBinding
    public AppProperties(String name, String version, int timeout, Security security) {
        this.name = name;
        this.version = version;
        this.timeout = timeout;
        this.security = security;
    }
    
    @Getter
    public static class Security {
        private final String jwtSecret;
        private final long jwtExpiration;
        
        public Security(String jwtSecret, long jwtExpiration) {
            this.jwtSecret = jwtSecret;
            this.jwtExpiration = jwtExpiration;
        }
    }
}
```

### 2-3. 조건부 주입 (@ConditionalOnProperty)

```java
@Component
@ConditionalOnProperty(name = "feature.enabled", havingValue = "true")
public class FeatureService {
    // feature.enabled=true일 때만 빈으로 등록
}

@Configuration
@ConditionalOnProperty(
    prefix = "cache", 
    name = "type", 
    havingValue = "redis"
)
public class RedisConfig {
    // cache.type=redis일 때만 설정 활성화
}
```

### 2-4. 조건부 주입(특정 Porfile인 경우)

```java
@Component
@Profile("dev")
public class DevService {
    // dev 프로파일에서만 활성화
}

@Component
@Profile("!prod")
public class NonProdService {
    // prod 프로파일이 아닐 때만 활성화
}

@Service
public class ProfileAwareService {
    
    @Autowired
    private Environment env;
    
    @PostConstruct
    public void init() {
        if (env.acceptsProfiles(Profiles.of("dev"))) {
            // 개발 환경 설정
        } else if (env.acceptsProfiles(Profiles.of("prod"))) {
            // 운영 환경 설정
        }
    }
}
```
