# 다국어 전략

## 1. MessageSource

MessageSource는 다국어(i18n) 시스템의 핵심 엔진으로 프로젝트에서 사용하는 모든 메시지(문구, 에러 메시지, 알림 메시지 등)를 Locale(언어) 기준으로 찾고 반환하는 역할을 담당한다.

 - 스프링에서는 message.properties, message_ko.properties 같은 메시지 파일을 읽어서 요청된 Locale(ko, en 등)에 맞는 메시지를 반환하는 컴포넌트
 - __MessageSource 주요 기능__
```java
// 1. 메시지 반환
messageSource.getMessage("welcome", null, locale);

// 2. 언어별 메시지 fallback 지원
// messages_ko_KR.properties → messages_ko.properties → messages.properties 순으로 탐색

// 3. 메시지 파라미터 치환 지원
// greeting=안녕하세요 {0}님!
messageSource.getMessage("greeting", new Object[]{"홍길동"}, locale);
```
<br/>

 - __MessageSource 동작 구조__
```
1) 클라이언트 요청 (Accept-Language, lang 파라미터 등)
2) LocaleResolver가 Locale 결정
3) MessageSource가 해당 Locale 메시지 파일 검색
4) 메시지 반환
5) Thymeleaf, Controller, Service에서 표시
```

 - __MessageSource 커스텀 설정__
    - messages, errors 처럼 여러 개 묶어서 사용 가능.
```yml
spring:
  messages:
    basename: messages, errors
    encoding: UTF-8
    fallback-to-system-locale: false
```
<br/>

### 1-1. message.properties

 - Spring Boot에서 다국어 메시지를 저장하는 파일이며 MessageSource 가 해당 파일들을 읽어 메시지를 제공한다.
 - 더 구체적인 Locale 파일이 가장 높은 우선순위

```
src/main/resources/
 └─ messages.properties            (기본)
 └─ messages_ko.properties         (한국어)
 └─ messages_en.properties         (영어)
 └─ messages_ja.properties         (일본어)
```
<br/>

 - `다른 폴더에 모으기`
```yml
spring:
  messages:
    basename: i18n/messages
    encoding: UTF-8
```

### 1-2. LocaleResolver

 - LocaleResolver는 현재 요청이 어떤 언어 Locale을 사용할지 결정하는 컴포넌트이다.
 - MessageSource는 LocaleResolver가 결정한 Locale을 기준으로 메시지를 고른다.
 - `AcceptHeaderLocaleResolver (기본)`
    - 별도 설정 안 하면 기본 적용
    - HTTP 헤더 Accept-Language 읽어서 Locale 결정
    - REST API, 모바일 환경에 적합
```
Accept-Language: en-US
```

 - `SessionLocaleResolver`
    - 세션에 Locale 저장
    - URL 파라미터로 언어 변경 가능(?lang=ko)
    - Thymeleaf 기반 다국어 UI서 가장 많이 사용
 - `LocaleChangeInterceptor (언어 변경)`
    - 이번 요청에서 `?lang=ko` 같은 파라미터를 읽어서
    - SessionLocaleResolver 또는 CookieLocaleResolver에 Locale 설정.
```
/home?lang=en
```
 - `CookieLocaleResolver`
    - LANG 쿠키를 사용해 Locale 결정
    - SPA 프론트와 합이 좋음

<br/>

#### LocaleResolver 우선순위

 - 1️⃣ URL 파라미터(lang=xx) → LocaleChangeInterceptor
 - 2️⃣ 세션(SessionLocaleResolver)
 - 3️⃣ 쿠키(CookieLocaleResolver)
 - 4️⃣ Accept-Language 헤더(AcceptHeaderLocaleResolver)
 - 5️⃣ LocaleResolver의 기본 Locale 설정값
