# 예외 처리 전략

## 1. 기본 예외 처리 흐름

 - 예외 발생 → DispatcherServlet → HandlerExceptionResolver들 동작
```
1. ExceptionHandlerExceptionResolver
 - @ControllerAdvice + @ExceptionHandler

2. ResponseStatusExceptionResolver
 - @ResponseStatus 또는 ResponseStatusException

3. DefaultHandlerExceptionResolver
 - 스프링 내부 에러 변환 (HttpRequestMethodNotSupportedException → 405 등)

4. ErrorController(/error)로 강제 포워드
 - Spring Boot는 BasicErrorController를 기본 구현으로 등록하고 있다.
 - DispatcherServlet이 해결 못한 예외는 자동으로 /error 로 포워드한다.
 - BasicErrorController가 요청 타입에 따라 응답 선택
    - BasicErrorController는 클라이언트 요청의 Accept 헤더를 통해 에러 템플릿을 반환
    - /templates/error/401.html
    - /templates/error/4xx.html
    - /templates/error/5xx.html
    - /templates/error.html
    - (없으면) Whitelabel Error Page

5. Tomcat 예외 페이지
```

## 2. 커스텀 오류 페이지설정

 - `Whitelabel Error Page 비활성화`
```yml
server.error.whitelabel.enabled: false
```
<br/>

 - `에러 템플릿 화면 생성`
```
src/main/resources/templates/error/401.html
src/main/resources/templates/error/403.html
src/main/resources/templates/error/404.html
src/main/resources/templates/error/500.html
src/main/resources/templates/error/error.html
```
