# 팔로우 서비스

## 팔로우 엔티티

 - __follows__
    - id
    - follower_id
    - followee_id
    - deleted_at
 - __삭제 방식__
    - `하드 삭제`
        - 데이터 복구 불가
        - 감사 추적 없음
        - 데이터베이스 크기 작음
        - 쿼리가 단순함
    - `소프트 삭제`
        - 데이터 복구 가능
        - 사용자 행동 분석 가능
        - 데이터베이스 크기 큼
        - 쿼리에 deleted_at IS NULL 필요
 - __팔로우 카운트 문제__
    - `FollowCount 엔티티`
        - user_id
        - followers_count
        - followees_count
        - 
```sql
SELECT COUNT(*) 
FROM follows 
WHERE follower_id = 1 AND deleted_at IS NULL;

SELECT followers_count, followees_count
FROM follow_counts
WHERE user_id = 1 AND deleted_at IS NULL;
```

## 팔로우 동시성 문제

 - __비관적 잠금__
    - 동시성 낮음
```
SELECT FOR UPDATE
UPDATE count = 101
COMMIT
```

 - __낙관적 잠금__
    - 동시성 높음
    - 재시도 필요
```
SELECT (v=1)
UPDATE WHERE v=1 (OK)
```

 - __원자적 업데이트__
```
UPDATE count = count + 1
```

 - __분산 잠금__
```
1. 잠금 획득 lock:user:10
2. DB 작업 실행
3. 잠금 해제
```


## 데이터베이스 선택

 - PostgreSQL
    - 부분 인덱스: 소프트 삭제 쿼리 최적화
    - JSONB: 유연한 메타데이터 관리
    - READ COMMITED: 높은 읽기 성능
    - 허용적 라이선스: 법적 문제 없음
    - 풍부한 커뮤니티: 활발한 생태계 및 확장 기능
