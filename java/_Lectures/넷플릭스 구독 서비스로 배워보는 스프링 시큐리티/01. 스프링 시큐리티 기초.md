# 스프링 시큐리티 기초

## 1. 스프링 시큐리티 기초

스프링 시큐리티는 인증 프로세스를 구현하기 위해 여러 컴포넌트로 구성되어 있다.
 - __인증 필터__: 인증 필터는 인증 요청을 가로채 인증 관리자에게 위임
 - __인증 관리자__: 인증 관리자는 인증 논리를 구현하는 인증 공급자를 이용하여 인증을 처리
 - __인증 공급자__: 인증 공급자는 사용자 관리 책임을 구현하는 사용자 세부 정보 서비스를 인증 논리에 이용. 또한, 암호 관리를 구현하는 암호 인코더를 인증 논리에 이용
    - 사용자 세부 정보 서비스(UserDetailsService): 사용자를 찾을 수 있도록 한다.
    - 암호 인코더: 암호를 검증한다.

```java
// UserDetailsService
public interface UserDetailsService {
    UserDetails loadUserByUsername(String username) throws UsernameNotFoundException;
}

// PasswordEncoder
public interface PasswordEncoder {
    String encode(CharSequence rawPassword);
    boolean matches(CharSequence rawPassword, String encodedPassword);
    default boolean upgradeEncoding(String encodedPassword) { return false; }
}
```
<br/>

 - `HTTP Basic 인증`
    - 사용자의 이름과 비밀번호를 Base64 인코딩하고 "Basic " 이라는 prefix와 함꼐 하나의 문자열로 HTTP Authorization 헤더에 담아 서버로 전달
    - Base64 인코딩으로 전송 중에 자격 증명이 탈취당하면 누구든지 해석이 가능하다.
    - 최소한의 기밀을 위해 HTTPS를 함께 이용하는 것이 좋다.
 - `HTTP 및 HTTPS`
    - HTTPS를 활성화하기 위해서는 인증 기관(CA, Certification Authority)이 서명한 인증서가 필요하다.
    - 인증서를 이용한다는 것은 클라이언트가 받는 응답이 인증 서버에서 보낸 것이라는 점을 알 수 있다.
    - 테스트 용으로는 OpenSSL 같은 툴을 이용할 수 있다.
 - `OpenSSL을 활용하여 자체 서명 인증서 구성`
    - server.ssl.key-store-type: PKCS12
    - server.ssl.key-store=classpath: certificate.p12
    - server.ssl.key-store-password: password
```bash
openssl req -newkey rsa:2048 -x509 -keyout key.pem -out cert.pem -days 365

# 자체 서명 인증서 생성
openssl pkcs12 -export -in cert.pem -inkey key.pem -out certificate.p12 -name “certificate”
```

### 1-1. UserDetailsService & PasswordEncoder

기본적으로 스프링 부트 애플리케이션을 실행하면 InMemoryUserDetailsManager가 등록되어 비밀번호를 UUID로 만들어서 콘솔에 출력한다.

 - 커스텀하게 UserDetailsService를 설정하면, PasswordEncoder도 함께 지정해주어야 한다.
```java
@Configuration
public class SecurityConfig {
    // 인메모리용 사용자 정보 서비스 등록
    @Bean
    public UserDetailsService userDetailsService() {
        InMemoryUserDetailsManager userDetailsManager = new InMemoryUserDetailsManager();
        UserDetails user1 = User.builder()
                .username("test")
                .password("1234")
                .build();
        userDetailsManager.createUser(user1);
        return userDetailsManager;
    }

    // 문자열 그대로 사용하는 인코더 등록
    @Bean
    public PasswordEncoder passwordEncoder() {
        return NoOpPasswordEncoder.getInstance();
    }

    // 엔드 포인트에 따른 접근 권한 부여 재정의
    public SecurityFilterChain securityFilterChain(HttpSecurity httpSecurity) throws Exception {
        return httpSecurity
                .authorizeHttpRequests((auth) -> auth.anyRequest().authenticated())
                .httpBasic(withDefaults())
                .build();
    }
}
```

 - `인증 공급자`
    - AuthenticationProvider는 인증공급자에 해당하는 부분으로 인증 논리를 구현하고 사용자 관리와 비밀번호 관리를 각각 UserDetailsService와 PasswordEncoder에 위임한다.
    - 커스텀하게 구현하기 위해서는 AuthenticationProvider를 상속받아서 구현한다.
```java
@Component
public class CustomAuthenticationProvider implements AuthenticationProvider {
    @Override
    public Authentication authenticate(Authentication authentication) throws AuthenticationException {
        String username = authentication.getName();
        String password = String.valueOf(authentication.getCredentials());

        if ("test".equals(username) && "1234".equals(password)) {
            return new UsernamePasswordAuthenticationToken(username, password, List.of());
        }

        throw new AuthenticationException();
    }

    @Override
    public boolean supports(Class<?> authentication) {
        return UsernamePasswordAuthenticationToken.class.isAssignableFrom(authentication);
    }
}
```

## 2. UserDetails와 사용자 관리

 - `사용자 관리`
    - 사용자를 표현하는 UserDetails
    - 권한을 표현하는 GrantedAuthority
    - UserDetailsService, UserDetailsManager를 활용하여 사용자 만들기, 암호 수정 등의 커스텀한 작업 지원
    - 다양한 유형의 UserDetailsManager (InMemoryUserDetailsManager, JdbcUserDetailsManager 등)
 - `사용자 관리를 위한 인터페이스`
    - UserDetailsService는 사용자 이름으로 사용자를 검색(READ)
    - UserDetailsManager는 사용자 검색, 추가, 수정, 삭제 작업 수행(READ, CREATE, UPDATE, DELETE)
        - READ와 WRITE 관련 인터페이스가 분리된 형태
        - 사용자 인증하는 기능만 필요하면 UserDetailsService 인터페이스만 구현
        - 추가, 수정, 삭제 등 더 많은 기능이 필요하면 UserDetailsManager를 함께 구현
    - GrrantedAuthority: 사용자가 수행할 수 있는 작업을 나타내는 이용 권리의 집합

```java
// UserDetailsManager -> UserDetailsService -> UserDetails -> GrantedAuthority

// 사용자 권한
public interface GrantedAuthority extends Serializable {
    String getAuthority();
}

// UserDetails는 하나 이상의 GrantedAuthority를 가짐
public interface UserDetails extends Serializable { 
    Collection<? extends GrantedAuthority> getAuthorities();
    String getPassword();
    String getUsername();
    // ..
}

// UserDetailsService는 UserDetails 인터페이스를 이용함
public interface UserDetailsService {
    UserDetails loadUserByUsername(String username) throws UsernameNotFoundException;
}

// UserDetailsManager는 UserDetailsService를 확장함
public interface UserDetailsManager extends UserDetailsService {
    void createUser(UserDetails user);
    void updateUser(UserDetails user);
    void deleteUser(String username);
    void changePassword(String oldPassword, String newPassword);
    boolean userExists(String username);
}
```
